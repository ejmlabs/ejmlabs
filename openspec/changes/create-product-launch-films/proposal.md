# Proposal

## Why

The project launch needs three short films that show useful work in the actual products. The films must use genuine product output, read well in an X feed, and reach a finished, checked MP4 rather than stop at a storyboard or preview.

## What Changes

- Add an isolated launch-film workspace with three product stories, reproducible capture instructions, source records, editable composition, posters and final exports.
- Present three scripts and timed visual storyboards for review before more capture or rendering. State each product's category, useful task, visible result and next action.
- Tell three distinct stories: CLI keeps many managed agents within shared work limits, IDE helps people read and follow source, and harness combines a fast core, a clear API and application tools. Retain earlier captures and story drafts as history rather than proof of these new narratives.
- Make open source part of every story. Invite viewers to try the project, inspect the source and help improve it through feedback, profiling, docs or code. Keep one clear invitation on each closing frame.
- Support speed and resource claims with scoped measurements. Distinguish managed sessions from executing jobs, configured capacity from measured capacity, native engine overhead from model latency, and recorded benchmarks from current product capture.
- Use local replay providers to keep captures repeatable, with real tools, file effects, test results and accurate replay disclosure in the source notes.
- Add any reusable timed terminal-capture contract in its owner, ejm-ui, before the films consume that public contract.
- After the user approves the stories, capture a distinct problem, action and outcome for each product. Use established local media tools for punchy modern edits, the canonical brand assets, readable detail cuts and upbeat lo-fi with verified rights.
- Review actual Cursor, OpenAI and Anthropic launch footage, then apply its observed task, action and result structure with purposeful camera changes and an uncluttered product canvas.
- Check final playback, frames, duration, codecs, audio, source fidelity, content safety and source attribution before delivery.

## Capabilities

### New Capabilities

- `product-launch-films`: Short product films with real capture evidence, consistent studio identity, editable sources and checked final exports.

### Modified Capabilities

None.

## Impact

- **ejmlabs:** owns launch stories, composition, public asset assembly and delivery notes under a new `launch-videos/` workspace. It consumes public product commands and SDKs, public capture contracts and canonical token assets. The website runtime and its bundle remain unchanged.
- **ejm-ui:** owns a reusable recording extension if the existing still capture cannot supply timed terminal footage. It has no OpenSpec root, so its normal owner checks and docs cover the contract before adoption.
- **ejm-cli, ejm-ide and ejm-harness:** remain owners of product behavior. Captures run isolated source snapshots and disposable workspaces through their existing commands and APIs. Test-only IDE startup instrumentation stays in the isolated capture copy and is recorded as such.
- Dependency direction stays from launch composition to public UI assets/capture and product APIs. No shared runtime depends on a consuming product or the films.
- Final MP4s and raw recordings stay out of website bundles. No account, repository visibility, release installer, production deployment or social post changes.
