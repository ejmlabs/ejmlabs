# Proposal

## Why

The user requires every project to keep its public docs current, honest, and detailed after every change. Current guidance routes readers to guides but does not consistently require a docs review, useful depth, or evidence of publication.

## What Changes

- Add an explicit public docs rule to `AGENTS.md` and all six project skills.
- Require docs review with every change, updates to affected pages, and a reason when no public docs are affected.
- Require useful user and developer detail and honest statements about availability, testing, security, performance, and release status.
- Document the studio's discovery-link ownership, product guide ownership, source files, checks, and publication evidence in the contributor and site guides.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `agent-engineering-policy`: require current, honest, detailed public docs in every instruction entry point.
- `documentation-discovery`: keep studio guide links aligned with the product-owned guides and verify publication before claiming the live site is current.

## Impact

This changes seven instruction files, two contributor guides, and their policy specs. It changes no application behavior, dependencies, tests, deployment, or release gates.
