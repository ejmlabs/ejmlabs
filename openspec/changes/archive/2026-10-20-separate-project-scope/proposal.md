# Proposal

## Why

The open source projects contain references and operational records from a separate proprietary business. This confuses ownership, licensing, documentation, and service boundaries.

## What Changes

- Keep studio instructions, guides, specifications, and retained audit records within the open source project scope.
- Remove unrelated product names, hosts, source links, credential references, and account inventory entries.
- Keep archive provenance honest by marking filtered records and preserving relevant observations without inventing replacement evidence.
- Add a lasting rule that keeps the open source projects independent of unrelated proprietary products.
- Check retained downloads and launch source archives for the same boundary.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `agent-engineering-policy`: Require independent open source identity and project-scoped evidence across instructions and files.
- `public-web-access`: Describe private service protection without importing another product's identity or operations.
- `cloudflare-service-security`: Limit retained inventories to project resources when an account also holds unrelated services.

## Impact

The owner is `ejmlabs`: studio guidance, public discovery, security operations documentation, and retained records. Public `@ejm/*` interfaces and dependency direction stay unchanged. The harness owns package manifests, registry behavior, and registry resource identifiers; the CLI and IDE own their guides and fixtures. Those repositories need their own scoped changes and owner checks. No deployment, account operation, credential rotation, Git history rewrite, or proprietary source change is part of this cleanup.
